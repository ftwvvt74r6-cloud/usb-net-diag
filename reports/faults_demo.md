## 二、问题详解

### 1. 建立 TCP 连接这一步失败或偏慢（严重）

- **所在层**：L4 传输层　**协议**：TCP
- **看到的现象**：表现是：访问这个地址时一直转圈，最后提示「无法连接」或连接超时。网络本身可能是通的，卡在「建立连接」这一步 —— 要么对方端口没有服务在听，要么中间的防火墙/安全组把包丢了。具体：1 个连接发出 SYN 后始终没有收到回应，TCP 三次握手未完成
- **专业依据**：1 个连接发出 SYN 后始终没有收到回应，TCP 三次握手未完成｜证据：10.0.0.5:8080（SYN 3 包）｜帧 #35,#36,#53
- **怎么处理**：先用「连通与速度测试」测目标端口是否可达；再查中间防火墙/安全组是否放行该端口、目标服务是否只监听 127.0.0.1、路由是否回指正确。

### 2. 链路上在丢包，实际速度被拖慢（严重）

- **所在层**：L4 传输层　**协议**：TCP
- **看到的现象**：表现是：网页加载到一半卡住、远程桌面一顿一顿、文件传输速度上不去。数据发出去没被对方确认，只能重发；重发越多，有效速度越低。这是链路质量问题，不是应用问题。具体：TCP 重传率 5.56%（2/36 个报文），乱序 0.00%，重复 ACK 0.00%
- **专业依据**：TCP 重传率 5.56%（2/36 个报文），乱序 0.00%，重复 ACK 0.00%｜证据：Stream 3 192.168.1.100→93.184.216.40:443 重传 2 次
- **怎么处理**：重传=发出去的数据没收到确认，等于丢包。先看是否集中在少数对端（对端或中间链路问题），再看是否全网段都高（本机网卡/上行链路问题）。排查顺序：网线/光模块 → 交换机端口（CRC 错包、双工不匹配）→ 无线信号 → 运营商链路。

### 3. 服务端响应异常（严重）

- **所在层**：L7 应用层　**协议**：HTTP
- **看到的现象**：表现是：网页能打开，但很慢，或者直接报 500/502。网络是通的，问题在服务端处理或应用本身。具体：1 个请求返回 5xx（服务端错误，占 50%）
- **专业依据**：1 个请求返回 5xx（服务端错误，占 50%）｜证据：状态码分布：200×1、500×1
- **怎么处理**：5xx 是服务端自己的问题，网络背锅不成立。按状态码查应用日志：500 看异常栈、502/504 看反向代理到后端的连通与超时、503 看是否过载/限流。

### 4. 同网段内找不到对方（ARP 无应答）（警告）

- **所在层**：L2 本地链路　**协议**：ARP
- **看到的现象**：表现是：同一个网段内的设备互相访问不了。二层地址解析都没有回应，说明对方没开机、IP 冲突，或者被划到了不同 VLAN。具体：1 个同网段地址的 ARP 请求没有得到应答
- **专业依据**：1 个同网段地址的 ARP 请求没有得到应答｜证据：192.168.1.50
- **怎么处理**：同网段内 ARP 不通，说明对方没开机、IP 冲突、或者接在了不同 VLAN。如果这就是网关地址，那么整台机器的外网访问都会断。

### 5. 网络层不通，被设备拦截（警告）

- **所在层**：L3 网络层　**协议**：ICMP
- **看到的现象**：表现是：某个网段或某台主机完全连不上。ICMP 的提示直接指明了原因：端口不可达=服务没起，主机不可达=路由/防火墙拦了，需要分片=路径 MTU 不匹配。具体：收到 1 条 ICMP 不可达、0 条超时
- **专业依据**：收到 1 条 ICMP 不可达、0 条超时｜证据：192.168.1.1→192.168.1.100 端口不可达(帧 #54)
- **怎么处理**：「端口不可达」= 网络通但服务没起；「主机/网络不可达」= 路由或防火墙拦截；「需要分片」= 路径 MTU 小于报文长度，需在 VPN/隧道接口下调小 MTU（如 1400）或修正 MSS。

### 6. 域名解析（DNS）出了问题（警告）

- **所在层**：L7 应用层　**协议**：DNS
- **看到的现象**：表现是：网址打不开，但直接用 IP 能打开；或者每次打开网页前都要愣几秒。这一步是上网的第一跳，DNS 慢会让所有网站都显得慢。具体：域名解析失败率 29%（NXDOMAIN 2/7）
- **专业依据**：域名解析失败率 29%（NXDOMAIN 2/7）｜证据：nx1.example.com.cn 失败 1 次；nx2.example.com.cn 失败 1 次
- **怎么处理**：先确认 DNS 服务器地址是否写错、域名是否拼错；若配置正常且集中在随机域名，再考虑 DNS 劫持或恶意程序。企业网内可对比 nslookup 与公共 DNS 的结果。

| 协商速率 / 频段 / 信道宽度 | 速率被压到很低会让 RTT 抖动、吞吐下降，需要确认终端与 AP 的实际协商结果。 | 无线控制器/AP 管理后台终端详情页的速率与频段信息。 | 协商速率与 AP 配置、终端能力匹配；不应长期停留在 1/2/5.5/11 Mbps 这类低速档。 |
| 空口时延 / 信道利用率 / 空口重传率 | 空口拥塞会让该 AP 下所有终端一起慢，需与有线侧对比后才能把问题归到无线侧。 | 无线控制器/AP 管理后台的性能统计或射频统计页。 | 信道利用率 < 60%，空口重传率 < 10%；持续高于该值视为无线侧劣化。 |
| 漫游记录 / 关联与认证事件 | 频繁漫游或反复认证失败会造成短时断流，对应业务上的间歇性超时。 | 无线控制器/AP 管理后台的终端事件、漫游或认证日志。 | 抓包窗口内无频繁漫游与反复认证失败；若有，请给出切换时间点与前后 AP 名称。 |

### 3. 有线接入侧

有线接入的端口统计、VLAN 与镜像配置在接入交换机上；请网络组提供故障终端所接端口同一时间窗的数据。

| 字段名 | 为什么需要 | 在哪看 | 判断标准或期望值 |
|---|---|---|---|
| 接入交换机端口状态 / 速率 / 双工 | 端口 down、速率协商异常或半双工会造成冲突、丢包与间歇不通（对应 L2/L4）。 | 接入交换机的端口状态页，或设备命令行里的接口摘要。 | 端口 up，速率与双工和对端一致；不出现半双工。 |
| 端口 CRC 错误 / 丢弃 / 溢出计数 | 物理层错误会表现为重传、乱序和间歇超时，是判定「线路问题」的直接证据。 | 接入交换机的端口统计（错误计数）页。 | 抓包窗口内 CRC/丢弃计数没有持续增长；有增长需检查网线、光模块或端口。 |
| VLAN / 端口隔离 / ACL 配置 | VLAN 错配或端口隔离会让终端到网关、对端不通，需要确认二层路径是否放通。 | 接入交换机的 VLAN 与端口配置页。 | 终端所在端口 VLAN 与网关接口一致；没有阻断该终端流量的 ACL 或端口隔离策略。 |
| 端口镜像 / 抓包点配置 | 需要在接入侧复现同样流量时，必须确认镜像源端口、方向与是否丢包。 | 接入交换机的镜像（端口镜像/流量镜像）配置页。 | 镜像源端口与方向覆盖故障终端；镜像口不拥塞、镜像流量无丢弃。 |

### 4. 承载与出口侧

网关、防火墙、VPN 与专线的会话、策略与质量记录，是判断「问题是否在本地出口之上」的关键；请网络组按故障时段导出。

| 字段名 | 为什么需要 | 在哪看 | 判断标准或期望值 |
|---|---|---|---|
| 网关/防火墙会话表与 NAT 记录 | 会话建立失败、端口耗尽或 NAT 映射异常会造成建连失败（对应 L4 连接建立）。 | 防火墙/网关的会话表、NAT 表或连接跟踪页。 | 故障时段存在终端到对端的会话；NAT 映射正常，没有端口耗尽告警。 |
| ACL / 安全策略命中记录 | 策略拦截会表现为 SYN 无响应或特定端口不通，需要确认流量是否被拒绝。 | 防火墙/网关的策略命中日志或拒绝记录。 | 没有针对该终端、对端或端口的拒绝记录；若有，请给出规则名与命中时间。 |
| 出口链路 RTT / 丢包 / 带宽利用率 | 出口拥塞或专线劣化会同时影响多个对端，是「承载网问题」的直接证据。 | 出口路由器/防火墙的接口流量与链路质量监控页。 | 出口丢包 < 1%、带宽利用率 < 80%；超出时请给出具体时间段。 |
| QoS / 限速策略命中情况 | 限速或队列拥塞会造成 RTT 抖动与重传，需要确认故障流量是否命中低优先级队列。 | 网关/防火墙的 QoS 或带宽管理页。 | 故障流量未命中低优先级或限速队列；若有，请给出策略名与限速值。 |
| VPN / 专线隧道状态与丢包 | 隧道重建或加密设备负载过高会造成周期性中断与时延，需与物理链路质量区分。 | VPN 网关/专线设备的隧道状态与性能页。 | 隧道保持 up、无频繁重建；隧道侧丢包 < 1%。 |

### 5. 名称解析与地址

DNS/DHCP 的日志与负载在名称解析服务器上；请按故障域名与故障时段导出，注意只提供域名与响应码，不要附带用户身份信息。

| 字段名 | 为什么需要 | 在哪看 | 判断标准或期望值 |
|---|---|---|---|
| DNS 查询/响应日志（含响应码与耗时） | DNS 超时、SERVFAIL、NXDOMAIN 会直接表现为打不开（对应 L7 域名解析）。 | DNS 服务器的查询日志或解析审计页。 | 故障域名在故障时段有查询记录且返回 NOERROR；响应耗时 < 100ms。 |
| DNS 服务器负载与上游转发状态 | 解析服务器过载或上游不可达会造成大面积解析慢或失败，需要排除服务器自身问题。 | DNS 服务器的性能监控与转发/递归状态页。 | CPU、连接数在正常范围；上游转发无持续超时。 |
| DHCP 租约与地址池使用率 | 地址池耗尽或租约冲突会造成终端拿不到地址、地址冲突或频繁重连。 | DHCP 服务器的租约列表与地址池统计页。 | 地址池使用率 < 90%；终端租约正常续约，没有冲突记录。 |
| 域名分流 / 解析策略配置 | 内外网域名分流错误会把请求送到错误的 DNS，表现为只有部分域名失败。 | DNS 服务器或网关的域名分流、解析策略页。 | 故障域名按预期分流到内网或外网 DNS；没有错误转发。 |

### 6. 服务侧

服务端监控、应用日志与负载均衡状态由应用或服务台提供；请按接口与时间窗导出聚合指标，不要附带用户数据。

| 字段名 | 为什么需要 | 在哪看 | 判断标准或期望值 |
|---|---|---|---|
| 应用响应时间与错误率（服务端视角） | 首字节慢或 5xx 说明服务端处理慢或异常，需要与网络 RTT 区分（对应 L7 应用响应）。 | 应用监控/APM 或服务端访问日志的响应时间与状态码统计。 | P95 响应时间在服务承诺内，5xx 错误率 < 1%；超出时请给出时间段与接口。 |
| 后端依赖（数据库/缓存/第三方接口）耗时 | 后端依赖慢会放大应用响应时间，表现为「网络没问题但业务慢」。 | 应用监控的后端依赖或链路追踪页。 | 依赖调用耗时在基线范围内；没有持续超时或连接池耗尽。 |
| 服务端连接数 / 线程池 / 队列水位 | 连接或线程耗尽会造成新连接被拒、请求排队，对应建连失败或超时。 | 服务端或负载均衡的连接数、线程池与队列监控页。 | 连接数与线程池使用率 < 80%，队列没有持续积压。 |
| 限流 / 熔断 / 降级事件 | 触发限流会返回 429/503，需要确认是否为服务端主动保护而不是网络故障。 | 网关/应用服务的限流与熔断监控页。 | 故障时段没有限流或熔断事件；若有，请给出触发规则与时间。 |
| 负载均衡健康检查与后端节点状态 | 负载均衡把流量打到异常节点会造成部分请求失败，需确认节点是否被摘除。 | 负载均衡/反向代理的健康检查与后端节点状态页。 | 所有后端节点健康；没有节点被摘除或权重异常。 |
