# 关键决策记录（ADR 精简版）

> 只记「为什么」，不记实现细节。新增决策按编号追加，不删除旧条目（被推翻时标「已改」）。

| # | 决策 | 理由 | 影响 |
|---|---|---|---|
| D01 | UI 默认入口切到 v2（旧界面保留 `?ui=v1`） | v2 有三段式报告与专业面板，v1 保留兼容 | `ui_entry` 优先级：`?ui=` > cookie > 配置 > 内置默认 |
| D02 | 报告固定「定性结论 → 证据 → 数据」三段 | 用户要先知道"哪里坏"，再要证据，再要数据；信息齐全但不聚焦=没人看 | `report.js` 为唯一实现，首页与五个模式页共用；证据/数据默认展开，明细才折叠 |
| D03 | 数值唯一来源 `rows()/metrics`，md / 复制文本 / json 同源 | 同一份数据四处各自渲染会打架（曾出现页面与导出矛盾） | 禁止在导出层重新判断一次 |
| D04 | ICMP 全丢但 TCP 可达 → 判「目标不响应 ICMP」，不判丢包/承载网 | 大量服务器/防火墙屏蔽 ICMP；按 ICMP 丢包判运营商是严重误判 | `core/probe_reason.py` 统一 reason（ok/icmp_filtered/refused/timeout） |
| D05 | 单目标模式的 impact 不升级为「影响整机」 | 一个目标不可达 ≠ 整机故障；曾误判并把责任推给本机 | 待修项 B1（`docs/backlog.md`） |
| D06 | 端口三级避让：8787 → 8788~8796 → 端口 0 | 端口被占不应等于本程序不可用 | 真实端口写 `logs/netdiag.port`；启动器/`find_running`/stop 脚本三处消费 |
| D07 | agent 采样样本 7 键恒在，取不到写 null 不删键 | 未来热力图/趋势按时间轴对齐，缺键会错位 | `gateway/dns` 拿不到用 null（不是 0，0 会被读成"0 丢包，网络极好"） |
| D08 | 事件判定：连续 2 次超阈值才落 1 条，恢复后重新武装 | 单次毛刺会导致事件刷屏 | 阈值从 `config/agent.json` 读，改配置立即生效 |
| D09 | 快照例外仅限 `reports/faults_demo.json` 三个字段 | 离线 meta 契约必须修根（`bpf` 里塞模式文案是错误数据） | `interface/bpf` 置空串 + 新增 `capture_mode`；已有 md 十份逐字节不变 |
| D10 | 文案面向企业环境：不出现「换公共 DNS」这类做不到的建议 | 企业内网通常只能走内部 DNS | 建议改为「请网络管理员核查 DNS 策略/内部备用 DNS」 |
| D11 | 不引入 pip 依赖，目标 Python 3.11 | 便携包用 3.11；3.12-only 语法（如嵌套 f-string）会在真实运行时崩 | 提交前 `compileall(3.11)` 必跑；CI 也守 |
| D12 | CI 只是入场券；本机实测 + 流程 C 陌生环境门禁才是放行依据 | CI 无 tshark/Npcap，且无法覆盖真实网络冲突 | 见 `docs/process.md` §3/§4 |
