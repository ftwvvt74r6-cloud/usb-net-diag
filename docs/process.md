# 开发与发布流程（A/B/C 三角色）

> 目的：任何人（或任何模型）接手，都能按同一套流程继续开发，不依赖聊天记录。
> 本文件是流程的**唯一权威**；与 `AGENTS.md`（硬约束）冲突时以 AGENTS.md 的「DO NOT」为准。

## 0. 角色

| 角色 | 职责 | 不做什么 |
|---|---|---|
| **Lead（主控）** | 分派任务、评审、合并 PR、打包、对外汇报 | 不直接写产品代码（紧急修复除外，需在记录里注明） |
| **A（UI）** | 只改 `ui/v2/**`（旧 `ui/index.html` 只在明确要求时改） | 不改 core/tests/scripts |
| **B（后端）** | 改 `core/` `tests/` `scripts/` `docs/` `launcher/` | 不改 `ui/v2/**`；需要 UI 配合时提「UI 需求单」 |
| **C（独立测试窗口）** | 黑盒测试：陌生环境、使用说明视角、冲突探测 | 不读源码、不改代码、不提交 git |

## 1. 一轮任务的标准循环

```
Lead 分派（任务卡：目标/边界/验收/产物目录）
   ↓
A 或 B 实现 → 自测（单测 + 变异）→ 本机实测（必须，见 §3）→ push 分支
   ↓
Lead：开 PR → CI 绿 → 评审（范围/证据/边界）→ 合并（merge commit）
   ↓
C：陌生环境门禁轮（P0=0 且 P1≤1 才放行）
   ↓
Lead：打包 → C 发布回归 → 交付
```

## 2. 硬性交付要求（每次都要）

1. **只 push 分支，不直接推 main**；一个任务一个分支，一个「逻辑阶段」一个 push（便于 Lead 增量合并）
2. PR/交付说明必须包含：动机、改了哪些层、验收命令与输出、回滚方式
3. **测试只增不减**，不许放宽断言；新增规则必须同时有「命中」和「不命中」用例
4. 红线（不可违反）：
   - demo + 9 个样本报告逐字节不变（例外必须显式声明并在 PR 里贴 diff）
   - `docs/api-reference.md` / `docs/docstring-gaps.md` 只能由 `scripts/gen_api_doc.py` 生成
   - 禁止 pip 依赖；Python 目标版本 **3.11**（3.12+ 语法特性会破坏便携运行时）
   - 不写死真实 IP / 内网域名 / token；不把服务绑到 0.0.0.0
5. **路径一律相对**：文档与指令写 `<仓库根目录>`、`<包解压目录>`、`%USERPROFILE%\NetDiag-progress\<轮次>\`；不要出现某台机器特有的绝对路径
6. 产物目录：`%USERPROFILE%\NetDiag-progress\<轮次>\`（平铺，报告与截图同目录）；**产物不入库**

## 3. 本机实测（CI 只是入场券）

CI 跑在 Linux、没有 tshark、没有 Npcap，因此**CI 绿 ≠ 能用**。每个交付必须附：

1. 真实运行一遍完整用户路径：启动 → 诊断 → 看报告 → 导出/复制 → 退出（截图 + 关键输出）
2. 至少一项「陌生条件」：非管理员 / 端口被占 / 干净目录 / 无 Wi-Fi / 换台机器 / 缺组件
3. 明确写出「跑在什么环境、看到什么、与预期差异」

禁止用「单测通过」代替本机实测；禁止用 mock 结果扮演真机结果。

## 4. 流程 C（独立测试窗口）门禁

- 黑盒：只读使用说明与界面，不读源码
- 陌生环境：每轮记录**环境事实**（系统、是否管理员、网卡、网关、DNS、缩放/分辨率），不预设任何网络结构
- 冲突矩阵：端口占用 / 代理·VPN·TUN / 杀软·EDR / 多网卡 / IPv6 / 非管理员 / 无无线 / 公司内网 DNS / 睡眠唤醒 / 中文系统 / 高缩放 / 小屏
- 缺陷分级：P0 崩溃·数据丢失·误导性严重误判 / P1 功能不可用·口径矛盾 / P2 文案布局性能 / P3 建议
- 放行：P0=0 且 P1≤1（有规避说明）；打包后 C 再做一轮发布回归

## 5. 合并纪律

- 只允许 merge commit（不 squash）
- 禁止 force push；合并后删除分支
- 合并前 Lead 必须核对：`git diff --name-only <base>...<head> | grep -v '^<允许目录>/'` 为空（grep 用 `-F`）
- 合并后 Lead 记录到 `docs/records/INDEX.md`

## 6. 记录与交接

| 记录 | 位置 | 是否入库 |
|---|---|---|
| 每轮验收报告/截图（原始） | `%USERPROFILE%\NetDiag-progress\<轮次>\` | 否（含环境信息/体积大） |
| 每轮索引（一行） | `docs/records/INDEX.md` | 是 |
| 关键决策与理由 | `docs/decisions.md` | 是 |
| 待办与已知缺口 | `docs/backlog.md` | 是 |
| 版本记录 | `CHANGELOG.md` + `docs/release-*.md` | 是 |
| AI 接手入口 | `docs/HANDOVER-AI.md`、`docs/START-HERE.md` | 是 |

### 红线补充：别让本地试验覆盖快照

`reports/faults_demo.*` 是金标准快照（CI 守门）。任何在仓库根目录直接跑离线分析
（`python core/diagnose.py --pcap ...`）都会重写这两份文件（含生成时间），必须立刻恢复：

```bash
git checkout -- reports/faults_demo.json reports/faults_demo.md
```

需要保留试验产物时，把输出目录指到 `%TEMP%`，不要在仓库里生成第二份。
